Echt (schreibt Datei + Issues) läuft nur die Action auf `main`; auf anderen Branches ist die Action ein Trockenlauf. Von Hand starten: Actions → waechter → Run workflow.
- **Alarm lesen:** `stats/alerts.md`. Gruppen: Daten, Action, Render, Clipfabrik, Tages-Short, Postzeit, Einreichen, Kampagne, Repo. Ein Issue pro Gruppe, `<!-- waechter-group: … -->` im Text; er aktualisiert den Text, schließt bei gelöstem Problem – aber nie bei „unsicherem" Lauf (Daten fehlten).

B. `short:2026-11-12`, `einreichen:tiktok:<id>` oder `postzeit:<Datum>:<short|kampagne>:<plattform>:<id>` – ein Präfix bis zu einem `:` genügt, z. - **Neue Kampagne:** Zeile in `plan/waechter.json` → `kampagnen` (`stats` = Name wie in `plan/stats.json`, `clips` = Ordner in `clips/`, `erwartet`, `bis`).

**Ablauf:** `plan/postplan.json` (Slot pro Clip: Datum, Zeit, Konto, Kampagne, Clip, Plattformen) → Aktion `einreichen` (`waechter/einreichen.py`) legt pro Berlin-Tag ein Issue „Einreichen <Tag>" mit einer Checkbox pro Clip an (Frist = Postzeit + 30 Min, Live-Links aus `stats/latest.json` werden nachgetragen) → Steven hakt am iPhone ab → die Aktion (Trigger `issues: edited`) schreibt den Haken als Slot-Schlüssel `konto|kampagne|datum|HH:MM` nach `plan/eingereicht.json` und schließt das Issue bei „alles abgehakt". Der Wächter holt vor jedem Lauf dieselben Haken aus den Issues (heilt einen verlorenen Push) und ordnet einen Live-Post dem nächsten Slot desselben Kontos/derselben Kampagne zu (±14 Min; TJR 09:00/09:30 bleiben getrennt).
**Eigenschaften:** Haken sind monoton (Datei ∪ Issue, nie zurück). Ein geschlossenes Issue zählt als komplett abgehakt (falls Steven nur „Schließen" tippt). Nur Issues des Actions-Bots mit unserer Markierung werden gelesen (das Repo ist öffentlich), der Issue-Text landet nie in Shell-Befehlen. Ein Post ohne Plan-Slot bekommt nach dem Live-Gang eine eigene Zeile (`post|<plattform>|<id>`), verspätet bis ~13 h (stats-Takt). Kommt eine Zeile zu einem schon geschlossenen Issue dazu, wird es wieder geöffnet + Kommentar (Benachrichtigung).
**Nicht live getestet:** `issues`/`workflow_run`-Trigger laufen nur auf `main`; Logik ist mit gefälschtem GitHub-Client getestet. Nach dem Merge: Aktion `einreichen` per Hand starten (Issue für heute prüfen), einen Haken tippen, prüfen dass `plan/eingereicht.json` einen Slot bekommt. **Ungeprüft: ob die Checkbox in der iOS-GitHub-App antippbar ist** – sonst im Issue-Text bearbeiten (Stift) oder das Issue schließen (zählt als abgehakt).
