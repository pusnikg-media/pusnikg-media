# Pusnik G Short-Pipeline (0 €)
1. `bash pipeline/setup.sh` (v2 seit 07.11.: espeak-ng per apt statt aus Quellcode, ca. 20 s)
2. `script.txt` – ein Satz pro Zeile (Englisch, letzte Zeile = CTA)
3. `python3 pipeline/tts.py script.txt vo am_puck 1.0` (Stimme: Kokoro am_puck, nie schneller als 1.0)
4. `python3 pipeline/music.py <sek> music.wav <seed>` (eigene Synthwave-Musik, lizenzfrei)
5. `job.json` (timing, music, out, day_label, hook, big, big_sub, cta) → `python3 pipeline/render.py job.json`
6. QA: `python3 pipeline/qa.py out.mp4` (ffprobe h264+aac 1080x1920, ebur128 ≈ -14 LUFS, kein Silence > 1 s, 3 Frames als PNG – Frame 0 zeigt Hook)
7. MP4 nach `shorts/` committen + pushen → URL: https://raw.githubusercontent.com/pusnikg-media/pusnikg-media/main/shorts/<datei>.mp4

## Preflight + QA (seit 07.11., spart Render-Zeit und Tokens)
- `python3 pipeline/preflight.py job.json` → `PREFLIGHT_OK …` oder `PREFLIGHT_FAIL` + genaue Liste (Exit 1). Prüft timing.json/WAVs, Anzahl `shots` = Skriptzeilen, jeder Clip existiert, dekodiert und ist lang genug für `start` + Slot (sonst friert das Bild ein), Musik, `card.line`/`card.word`, `punch`, Länge 18–35 s. Läuft automatisch am Anfang von `render_hf.py`.
- `python3 pipeline/qa.py out.mp4` → `QA_OK …` oder `QA_FAIL` + Liste (Exit 1): h264 1080x1920 + aac, A/V-Länge gleich, 18–35 s, −16…−12 LUFS, keine Stille > 1 s, kein Standbild > 2,5 s, Frame 0 nicht schwarz. Legt `out_qa_0.png`, `out_qa_mid.png`, `out_qa_end.png` neben das Video → diese 3 Bilder ansehen.
- Alle Pfade in job.json sind relativ zum job.json-Ordner. tts.py löscht ein altes `words.json`; Fehler enden immer mit `FAIL…`/`… FAIL` statt mit einem kaputten Video.

## Renderer v3 HyperFrames (STANDARD seit 04.11. abends, von Steven freigegeben) – `pipeline/hyperframes/render_hf.py`
`python3 pipeline/hyperframes/render_hf.py job.json` (Render ca. 3–4 Min, 0 Credits)
job.json: `vo_dir`, `shots` (pro Skriptzeile Liste `{"file","start"}`, Schnitte ≤2,3 s, Dateinamen eindeutig), `day`, optional `hook_big` (Standard = day), `hook_mid` ("DAYS LEFT"), `hook_sub` (Neugier-Zeile unter der Zahl, max. 22 Zeichen, seit 09.11. ab Frame 0 sichtbar), `badge`, `card` (Slam-Karte auf ein Schlüsselwort: `{"line","word","top","big","bottom"}`, z. B. NOV/19/2026 beim Wort „November"), `punch` (Liste von Wortanfängen, z. B. ["downgrade","console"]: Zoom-Punch 1,14→1 + kurzer Flash auf diesen Wörtern), `music`, `music_start`, `music_db` (−9), `out`.
Kann: wortgenaue Karaoke-Untertitel (Whisper base.en, auf echte Sprechzeit kalibriert, aktives Wort gelb + Pop), Riesen-Hook mit Pink-Glow im Frame 0, Slam-Karte, springender FOLLOW-Button auf der letzten Zeile, Ken-Burns-Zoom, Weiß-Flash pro Schnitt, Fortschrittsbalken, Stimme EQ+Kompressor, Musik geloopt + per Sidechain geduckt, −14 LUFS.
Dateien: `words.py` (Wort-Timing), `build_cd.py` (HTML-Komposition), `cd_template.html` (Look), `gsap.min.js`.

## Clip-Renderer v2 (Fallback) – `pipeline/render_clips.py`
`python3 pipeline/render_clips.py job.json`
job.json: `vo_dir` (tts.py-Ordner), `shots` (pro Skriptzeile Liste von `{"file","start"}`), `music` (Datei, geloopt), `music_start` (Intro überspringen, s), `music_db` (Standard −12, wird unter der Stimme automatisch abgesenkt), `badge` ("GTA 6 • DAY X"), `hook` (max. 6 Wörter), `out`, optional `gap` 0.22, `tail` 0.6, `max_shot` 2.3.

Musik: jeden Tag ein anderer Track – benutzte Tracks in `pipeline/music_log.txt` (Datum | Titel | Quelle) eintragen und vorher prüfen.

Quellen: `jobs/<name>.json` im Repo (im Chat angelegt) oder `job-<name>.json` im Drive-Ordner „Pusnik G Render-Aufträge" (ID 1sZgGx8xmJ5OX5UcGUhZn9u_UzenRGYwF, muss „Jeder mit dem Link" lesbar sein; vom geplanten Produzenten angelegt).

Fehlgeschlagene Aufträge werden bis zu 3-mal wiederholt. Seit 09.11. wirft gh_render.py unscharfe Clips raus (Laplace-Varianz < 15 bei 270x480), solange die Zeile noch einen anderen Clip hat. ## Clipfabrik v2 (seit 14.11.) – GitHub Action `.github/workflows/clipfabrik.yml`, Skript `pipeline/clipfabrik/clipfabrik.py`
Kampagnen-Footage → fertige 9:16-Clips (nur Originalton), ohne dass ein Claude-Lauf Code ausführt. Läuft bei Push auf `clipjobs/` und alle 30 Min.
- Auftrag: `clipjobs/<name>.json` im Repo oder `clipjob-<name>.json` im Drive-Ordner „Pusnik G Render-Aufträge". Felder: `name`, `source` (https-URL der offiziellen Datei: Release-Asset, öffentlicher Drive-Link oder Direktlink), optional `pill` (gelbe Pflichtzeile), `fix` (verhörte Namen), `min_len` (Standard 10), `clips` `[{"id","a","b","title", optional "wide","pill","captions","rev"}]`.
- Phase 1 (ohne `clips`): `clips/<name>/scan/scan.json` (Sätze mit Zeiten, Schnitte, Kandidaten 10–24 s an Satzgrenzen), `words.json`, `cand_XX.jpg` (4 Bilder je Kandidat – ansehen, dann ehrlichen Titel schreiben).
- Phase 2 (mit `clips`): `clips/<name>/<name>_<id>.mp4`, Vorschaubild `qa/<name>_<id>.jpg`, `clips/<name>/result.json` (`ok`, `phase`, pro Clip `url`). Unveränderte Clips werden nicht neu gerendert; aus dem Auftrag entfernte Clips werden gelöscht. Abgelehnte Aufträge (Clip < `min_len`, außerhalb der Quelle, Titel zu lang) stehen mit Grund in `error`.
- Titel: Teil vor „:" gelb; max. ca. 32 Zeichen. `wide: true` zeigt 75 % der Bildbreite (für Texttafeln).
- **v3 IRL (14.11.):** `source` darf auch eine VOD-Seite sein (Twitch, Kick, YouTube, TikTok, X, Rumble) → yt-dlp (Scan in 480p, Render in `max_height`, Standard 1080p, ab 3 h 720p). YouTube blockt Cloud-Server oft → dann Drive-/Direktlink nehmen.
  Quellen > 15 Min: Hotspot-Scan – Lautstärke-Spitzen gegen den gleitenden 3-Min-Grundpegel (Schreien, Lachen, Menge) + YouTube-„Most replayed“, nur diese Stellen werden transkribiert. scan.json: `mode: hotspots`, `regions`, Kandidaten mit `hype` (dB über Grundpegel) und `peak_in`. `hot_k` = Anzahl Stellen (Standard 14).
  `layout: "full"` = Vollbild-9:16 (ohne Unschärferand, Titel oben mit dunklem Verlauf, Untertitel unteres Drittel); `track: true` = Ausschnitt folgt dem größten Gesicht (OpenCV, ruhige Kamera mit Totzone; ohne Gesicht Mitte). Beides auch pro Clip. IRL-Standard: `"layout": "full", "track": true`.

## Clipfabrik v4 (15.11.) – Hook zuerst + Auto-Zoom
- `"hook": [s, e]` pro Clip (Quell-Sekunden, 0,8–5 s): dieser Moment läuft als Teaser VOR dem Clip, dann Weiß-Blitz und der Clip ab `a`. `"hook": "auto"` nimmt die lauteste Stelle nach den ersten 5 s (an Wortgrenzen; nichts, wenn nichts heraussticht). Besser: den stärksten Satz aus scan.json von Hand als `[s, e]` setzen.
- `"zoom": true/false` (Auftrag oder Clip): kurze 8-%-Zoom-Stöße auf die lautesten Momente (höchstens einer pro 4 s). Standard: an bei `layout: "full"`, aus bei `framed`.
- result.json pro Clip: `punches` (Anzahl Zoom-Stöße), `hook` (benutzter Teaser).

## Livewatch v0 (15.11., Prototyp) – `.github/workflows/livewatch.yml`, `pipeline/clipfabrik/livewatch.py`
„Fast live“: Läuft ein Kanal aus `plan/livewatch.json` gerade, nimmt der Runner den Stream in 60-s-Stücken auf, misst die Lautstärke gegen die letzten 10 Min und rendert bei einem klaren Ausreißer (`min_hype` dB, Standard 9) sofort einen 9:16-Clip → `clips/live-<kanal>/` + `inbox.json` (`url`, `qa`, `auto_title`, `said`, `hype`, `posted`). Clip liegt ca. 3–6 Min nach dem Moment im Repo.
- Einschalten: `plan/livewatch.json` → `"enabled": true`, `"channels": [{"name","url" (Kick/Twitch-Kanalseite),"min_hype":9,"per_hour":3,"max_clips":8,"height":720,"layout":"full","track":true,"fix":{}}]`. Die Action startet alle 20 Min, läuft bis 5,5 h am Stück und hört auf, wenn der Stream endet.
- Gepostet wird hier NICHT (keine Plattform-Schlüssel auf dem Runner): ein Agent liest inbox.json, sieht das QA-Bild an, schreibt Titel/Caption und postet über vidIQ.
- Getestet: Erkennung + Schnitt + Render per `livewatch.py simulate` (künstlicher Stream). Ungetestet: echte Live-Aufnahme (Kick/Twitch) auf dem Runner. Jeder Clip vergrößert das Repo (~10 MB) → `max_clips` klein halten.

## Reflab v0 (15.11.) – `.github/workflows/reflab.yml`, `pipeline/reflab/reflab.py`
Schaut sich ohne vidIQ-Credits an, was woanders funktioniert: holt pro Referenz-Konto aus `plan/reflab.json` die meistgesehenen der neuesten Shorts (yt-dlp), misst den Schnitt (Länge, Schnitte pro 10 s, erster Schnitt, wann gesprochen wird, Wörter pro s, die ersten Worte = Hook) und legt `refs/latest/report.json` + kleine Bildstreifen ab (`rXX_hook.jpg` = erste 3 s, `rXX_flow.jpg` = ganzer Clip). Eigene Clips (`ours`) werden zum Vergleich mitgemessen (`median_refs` gegen `median_ours`). Es werden keine fremden Videos gespeichert. Läuft montags und bei Änderung von `plan/reflab.json` (Konto oder einzelnen Link unter `urls` eintragen). `problems` zeigt, welche Plattform den Runner blockt.

## Clipfabrik v5 (15.11.) – Stil „native“ aus dem Reflab
Befund Reflab (16 virale Streamer-Clips kleiner Clipper-Konten, 80 Tsd.–5,6 Mio. Views): fast alle zeigen das GANZE Originalbild (16:9 mittig im Hochformat), EINEN Kontextsatz als weißen Kasten mit schwarzer Schrift direkt über dem Bild (normale Schreibweise, 1–2 Wörter groß, Emojis, Name des Streamers zuerst), Originalton, keine Wort-Untertitel, keine Zooms, 0 Schnitte im Median, 10–38 s (Median 17 s).
- `"layout": "native"` (Auftrag oder Clip): ganzes Bild, nichts abgeschnitten; Wort-Untertitel nur mit `"captions": true`, Zoom nur mit `"zoom": true`.
- `"caption": "<Kontextsatz>"` pro Clip (Emojis erlaubt): ersetzt den großen Titel; `title` darf dann fehlen. Geht auch mit `framed` und `full`. Seit 16.11. (Reel-Scout: 5 von 6 viralen Personen-Clips) ist der Satz ein ganzer Erzählsatz mit 9–15 Wörtern, Name zuerst, Ende „… 😭“. Der Kasten passt sich an: bis ca. 75 Zeichen 46 px, danach 42/38 px, höchstens 4 Zeilen (ca. 150 Zeichen), Zeilen werden gleich lang umbrochen. `result.json` nennt pro Clip unter `hints` weiche Stil-Hinweise zum Satz (zu kurz, kein Emoji, zwei Sätze, zu viele Großbuchstaben, Clip über 40 s) – gerendert wird trotzdem; ist ein Hinweis berechtigt, den Auftrag einmal korrigieren.
- `"layout": "split"` (Gaming mit Facecam): Gesicht oben (1080x720), Gameplay-Mitte unten (1080x1200), Kontextsatz auf der Naht. `"facecam": "auto"` (sucht das kleine Gesicht, das an einer Stelle bleibt) oder `[x, y, b, h]` als Anteile des Bildes (0–1) – beim Ansehen der cand-Bilder ablesen ist sicherer als auto. Ohne Facecam fällt der Clip auf `native` zurück. Mechanik getestet, automatische Erkennung an echtem Stream-Material noch nicht.

## Livewatch v0.5 (Fable-Nacht 16.11.2026) – wartet, bremst, Testmodus
- **Wartet auf den Streamstart:** Ist kein Kanal live, fragt `watch()` alle `poll_seconds` (Standard 90) neu, bis `max_minutes` oder `until` abläuft. Früher endete ein Offline-Lauf sofort und der nächste Start kam wegen GitHub-Cron-Verspätung 20 Min bis 3 h später. Der Lauf belegt dafür bis zu `max_minutes` den Runner (kostenlos). Folgeläufe stehen in der Warteschlange (`concurrency: livewatch`).
- **Repo-Bremse:** `max_pending` (Standard 12) = höchstens so viele Einträge mit `posted: false` aus den letzten 24 h in `clips/live-<kanal>/inbox.json`; danach nimmt Livewatch bis zum Ablauf des 24-h-Fensters nichts mehr auf (`LIVEWATCH_FULL` im Log). Das heißt höchstens ca. 12 × 10 MB = 120 MB pro Tag und Kanal (Clip + `raw_*.mp4`, Repo-Spielraum bis 3500 MB ca. 900 MB). Niemand muss aufräumen; wer sofort weitere Clips will, setzt Einträge auf `posted: true` (Chat-Session mit Schreibrecht auf `clips/`).
- **Aufwärmzeit:** In den ersten `warmup_s` (Standard 480 = 8 Min) einer Aufnahme wird nichts geclippt. Anlass: Live-Test 16.11. (zackrawrr, Profil gaming): 3 Clips in den ersten 9 Minuten (erwartet ca. 0,5 bei 3/h), alle drei Alltagsmomente ohne Höhepunkt (Browser-Fenster, Gespräch); die Chat-/Lautstärke-Basis einer jungen Aufnahme ist instabil. Nicht nachgemessen (kein zweiter Live-Lauf) – bei Talk-Streams eher Profil `irl` (4,5 / 2,5) nehmen.
- **Testmodus** (`workflow_dispatch`, kein `enabled` nötig, ändert `plan/livewatch.json` auf main nicht): Eingaben `urls` (Kanal-URLs, Komma-getrennt; der erste Live-Kanal wird aufgenommen), `minutes` (5–120), `profile` (`gaming`/`irl`). Clips landen trotzdem in `clips/live-<kanal>/` auf main → danach löschen (fremde Streamer, Repo öffentlich).
- **Clipfabrik/OpenCV:** Die Workflows installieren `opencv-python-headless<5` (ab 5.0 fehlt `CascadeClassifier`); ohne Gesichtserkennung fallen `facecam: auto` und `track` jetzt sauber auf native/Mitte zurück.

## Clip-Regression (Fable-Nacht 16.11.2026) – `tests/clip_regression.py`
Rendert native/native+captions/Hook/Sonderzeichen/full/full+track/framed/split/split-auto-ohne-Cam und eine Quelle ohne Ton auf einer synthetischen Quelle; Hash über dekodierte Frames und Ton, dazu Sync-Prüfung (Bild-/Tondauer < 0,1 s) und Frameanzahl. `python3 tests/clip_regression.py save VORHER` → Code ändern → `compare VORHER` (Exit 1 bei Abweichung). Im Repo: `tests/fixtures/clip_hashes.json` (Golden je ffmpeg-Build; auf fremdem Build prüft `test_clip_regression.py` nur die Struktur) und `python3 tests/clip_regression.py golden` zum Aktualisieren NACH bewusster Änderung. Dauer ca. 1 Min.
